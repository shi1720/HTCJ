# GroundProof API

All endpoints return JSON. An HTTP-only `groundproof_session` cookie authenticates a single operator workspace. Each registered operator owns an isolated workspace; shared multi-user organizations are outside this release. Errors have the shape `{ "error": "Human-readable message" }`.

## Authentication

| Method | Path | Request / result |
| --- | --- | --- |
| GET | `/api/health` | Public `{status:'ok',version:'1.0.0'}` |
| GET | `/api/auth/me` | Public `{user: User \| null}` |
| POST | `/api/auth/register` | `{name,email,password,workspace}` → `{user}` (201); empty workspace; password at least 12 characters |
| POST | `/api/auth/login` | `{email,password}` → `{user}`; rotates current browser session |
| POST | `/api/auth/logout` | Revokes current session and clears cookie |
| POST | `/api/demo/start` | Creates a fresh, isolated simulation and signs in → `{user}` (201) |

Account sessions expire after seven days. Demo sessions expire after 24 hours. Expired sessions and inactive demo workspaces older than 24 hours are removed at startup and hourly; real accounts are never removed by retention cleanup. Sign-in additionally has a persistent per-email budget of 10 attempts per 15 minutes, cleared after successful authentication. Demonstration accounts cannot sign in using a password. Register/login responses never contain password hashes or session tokens in JSON.

## Workspace operations

`GET /api/state` returns the canonical `AppState` from [`shared/types.ts`](../shared/types.ts), including server-derived evidence assessments and server time. Client-provided readiness is never accepted.

| Method | Path | Request |
| --- | --- | --- |
| POST | `/api/sites` | `{name,address,lat,lon}` |
| DELETE | `/api/sites/:id` | Only unreferenced sites can be removed |
| POST | `/api/sources` | `{title,url,category,siteId:null\|string,freshnessHours}` |
| POST | `/api/sources/record` | `{title,content,reference,category,siteId,freshnessHours,validUntil?:ISO\|null}` → operator-supplied record (201) |
| POST | `/api/sources/:id/record` | `{content,reference,validUntil?:ISO\|null,expectedHash}` → new record version |
| POST | `/api/sources/:id/capture` | `{provider:'direct'\|'anakin'}` |
| PATCH | `/api/sources/:id/monitor` | `{enabled,intervalHours,provider}`; explicit opt-in monitoring of real sources |
| POST | `/api/sources/:id/review` | `{expectedHash,decision:'accepted'\|'blocked',note}` |
| DELETE | `/api/sources/:id` | Only sources not required by any job can be removed |
| POST | `/api/missions` | `{name,client,siteId,scheduledAt,value,sourceIds}` |
| PATCH | `/api/missions/:id` | Any non-empty subset of creation fields; optional `expectedRevision` rejects stale edits; invalidates prior signature |
| DELETE | `/api/missions/:id` | Removes job; retains audit events |
| POST | `/api/missions/:id/approve` | `{expectedRevision,expectedHashes:{sourceId:hash,...},note}` |
| GET | `/api/missions/:id/export` | Self-contained evidence JSON download |
| POST | `/api/lab/run` | Executes rule checks and returns `LabReport` |

Names are 1–200 characters. Decision/sign-off notes are 8–2,000 characters. Source IDs are unique UUID references, checked against the authenticated workspace. Every job requires at least one source, with a maximum of 50. Site-specific sources must belong to that job's site. `scheduledAt` is an ISO timestamp including a timezone; future scheduled jobs are supported. Evidence capture/review/approval timestamps are generated by the server. Coordinates are illustrative planning metadata, never a flight route. Workspace limits: 200 sites, 200 sources and 1,000 jobs.

Live web sources currently support approved public HTTPS domains: `faa.gov`, `nps.gov`, `boston.gov`, `mass.gov`, `weather.gov`, and `noaa.gov`, including their subdomains. The backend validates DNS and redirect destinations; private/reserved addresses, credentials, non-HTTPS URLs and nonstandard ports are refused. Fixtures cannot be live-captured. Anakin use is explicit and never silently substituted with Direct capture.

Captures share a concurrency budget of two per workspace and eight per process. Evidence archives accept captures up to 100 MiB or 10,000 archived snapshots per workspace (a final in-flight capture can cross the byte threshold). Archive capacity does not silently delete historical evidence.

A failed capture returns 502, preserves the last successful snapshot, records the failure, and invalidates affected mission approvals. Conflicting concurrent captures return 409 rather than overwriting a newer snapshot. A content change removes the source's current review and invalidates all dependent signatures. Expired evidence refreshed with identical bytes still requires a new mission signature.

## Operator-supplied records

A record is a text excerpt supplied by the authenticated operator, not a fetched or independently authenticated document. Text must contain 50–20,000 characters; its one-line reference must contain 3–300. The operator retains the signed original or primary record and supplies its reference. Records use `kind:'record'`, `fixture:false`, and snapshot `provider:'manual'`. The internal `groundproof.invalid` URL is an identifier, not a link to the original.

Every snapshot includes a visible operator-supplied label, reference, optional declared validity and text in one hash-bound envelope. Editing reference or validity therefore changes the content digest too. An update requires the latest `expectedHash`, retains previous snapshots, clears the current review and invalidates dependent approvals. Even an identical explicit resubmission requires review. Record authenticity, signatures, legal sufficiency and the truth of the operator's statement are not verified.

An expired declared `validUntil` holds dependent jobs. A record that expires at or before a job's scheduled time also holds that job even if the record is currently in date. If validity is omitted/null, configured freshness still applies; the product does not infer an expiry. Operator records cannot enable web capture or automatic monitoring. Their owner must record updates when the primary evidence changes.

## Provider budget

Anakin reservations are atomic across this deployment database: default **30 attempted calls per UTC day**, with **3 per demo workspace per UTC day**. `ANAKIN_DAILY_LIMIT` configures the deployment limit from 0 to 10,000; invalid values or 0 disable Anakin calls. Failed upstream attempts still consume the conservative allowance. The global counter survives demo cleanup. Quota exhaustion returns 429 before any supplier request, preserves the snapshot, marks the source unavailable and revokes dependent approvals. Scheduled retries wait at least until the next UTC day. Direct capture is available only through an explicit provider selection; there is no silent fallback. These are cost controls, not a subscription billing system.

## Opt-in monitoring

Real sources can opt into scheduled Direct or Anakin captures using `PATCH /api/sources/:id/monitor`. `intervalHours` must be an integer between 1 and 168 and shorter than the source freshness window. Enabling schedules an immediate first attempt; disabling prevents subsequent attempts and leaves any already-running capture to finish. Sources default to monitoring off, and fixtures cannot enable monitoring.

Node checks due work at startup and every 60 seconds, attempting at most three sources per tick. Due work is claimed before I/O so overlapping ticks do not duplicate a capture. Manual and scheduled captures share the exact same persistence, error, integrity and signature-invalidation path. Successful captures schedule the next chosen interval; failures back off to twice the interval, capped at 24 hours and never shorter than the configured interval. Failures preserve the last snapshot, record an error and revoke dependent signatures. Every capture is audited as `Scheduled monitor`; source review and mission sign-off remain human actions. A restarted process resumes from persisted next-attempt times. Timing is best effort, not a guaranteed real-time feed.

## Concurrency and decisions

Review requires the exact latest content hash. A stale review returns 409. Blocked evidence places every dependent job on hold. Reviewing a source never signs a job.

Sign-off is transactional. `expectedRevision` is required and must equal the current mission revision (initially 0). Planning edits and dependency invalidations increment that persisted revision, so a stale dialog cannot sign a changed appointment or an A→B→A restored source using an old note. `expectedHashes` must contain exactly every required source and no extras. Every snapshot must pass its hash check, be fresh, be available, and have an accepted review. A source mutation and a concurrent sign-off cannot leave a job ready with an obsolete signature. Restoring previous bytes never revives a revoked signature.

`ready` means documentary sign-off complete. It is **not** flight authorization, airspace clearance, insurance validation or legal clearance.

## Demonstration operations

`POST /api/demo/drill` accepts `{scenario:'closure'|'stale'|'unavailable'|'restore'}`. `POST /api/demo/reset` recreates only the current demo workspace. Both return `AppState` and reject non-demo accounts with 403.

Every initial demo has six signed fictional jobs, three sites, and five fixture sources. The Harbor Works notice is required by exactly three jobs with $4,800 in illustrative planned value. The other three jobs remain unaffected. Restore clears the active notice problem but requires review and fresh signatures.

## Evidence bundle verification

The export includes `schemaVersion`, `exportedAt`, `scope`, `workspace`, `mission`, `site`, `sources`, `audit`, and `manifest`. `sources` contains the exact latest and preceding snapshots, their hashes, reviews and provider labels. Its manifest uses SHA-256 over all fields except `manifest`, encoded as UTF-8 JSON with object keys sorted recursively and array order preserved. Recompute each snapshot's SHA-256 from its exact UTF-8 `content` independently.

A matching manifest detects accidental or subsequent modification. It is not a digital signature, third-party timestamp, or assertion that a source statement is true. A party capable of rewriting the bundle can also recompute its digest. See the repository verifier and evidence design documentation.

Verify an exported packet offline:

```sh
npx tsx scripts/verify-packet.ts path/to/packet.json
npx tsx scripts/verify-packet.ts path/to/packet.json --expected-hash SHA256_FROM_A_TRUSTED_CHANNEL
```

The verifier independently re-encodes the canonical manifest, recomputes every snapshot digest, checks exact source coverage, provenance labels, site binding, timestamps and any claimed ready status. Exit code 0 means covered integrity checks passed; 1 means invalid content; 2 means invalid command usage. Supplying a digest saved independently helps detect replacement of the entire packet.
